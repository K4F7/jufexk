Part of #66

权威决策：ADR-0021。首版按已锁定共识实现评价规则驱动的任课评价投稿与展示，不逐类打磨特有维度。

## Problem Statement

任课评价现在只有总体评分强制必填，其余维度可省略；题目定义散落在投稿表单、接口校验和宽表列里，已经互相漂移。课程只有 `general` / `sports` 两种评价模板类型，无法按专业、思政、体育、高等数学、公共基础、大学英语区分必答维度，也无法表达「这门课是网课、没有线下签到」。公开评价流不展示维度均分；生产前端也还没有挂上投稿页。需要一份权威、版本化的评价规则同时驱动问卷、校验和落库，并让带补充说明的公开条目能看到维度均分。

## Solution

用代码内的评价规则定义六类课程的必答评分题。投稿者选好任课关系后，必须答完本次适用的评分题和本次推荐度；补充说明仍是一段选填文字。网课打上 `mooc` 课程标签后，仅线下适用的题（点名频率）不出现、也不必答。每条新评价记下当时的规则版本和各维度分数。公开文字评价流里，有规则版本的条目显示一个维度均分 Chip，不逐项展示维度。生产站点挂上投稿页，问卷由同一份规则渲染。

## User Stories

1. As a 投稿者, I want 评价必须绑定已有任课关系, so that 公开评价始终对应具体课程和任课教师
2. As a 投稿者, I want 选择课程后自动看到该类评价规则的题目, so that 我不用自己判断这门课该答哪几题
3. As a 投稿者, I want 本次推荐度作为单独一题且各规则类型题干一致, so that 我能给出综合判断而不是被维度均分代替
4. As a 投稿者, I want 上课表现、点名频率、给分情况、考核压力都必答, so that 每条新评价的维度齐全、可比较
5. As a 投稿者, I want 给分情况用「你感受到的给分」这类主观措辞, so that 我不会误以为在填写官方高分率或及格率
6. As a 投稿者, I want 补充说明是一段选填文字, so that 我可以解释分数，但不必为每个维度写说明
7. As a 投稿者, I want 不写补充说明也能提交有效评分, so that 我只想打分时不必硬写文字
8. As a 投稿者, I want 漏答任一适用评分题时被明确拦住, so that 我不会提交不完整的新规则评价
9. As a 上过网课的投稿者, I want 带 mooc 标签的课程不出现点名频率, so that 我不用回答线下签到这种不存在的题
10. As a 上过网课的投稿者, I want 网课仍按学科走原来的评价规则, so that 思政网课仍是思政类、英语网课仍是大学英语类
11. As a 投稿者, I want 问卷用站点现有的表单、单选和多行文本控件, so that 填写体验和站内其他表单一致
12. As a 投稿者, I want 从站点导航进入写评价页, so that 我不必再走已退役的旧页面
13. As a 浏览者, I want 有补充说明的任课评价显示一个维度均分 Chip, so that 我能一眼看到这次各必答维度的平均分
14. As a 浏览者, I want 没有规则版本的旧评价不显示维度均分, so that 系统不会伪造旧数据的维度
15. As a 浏览者, I want 评价流不逐项列出各维度分数, so that 列表保持现在的匿名文字流密度
16. As a 浏览者, I want 没有补充说明的有效评分不进入文字评价流, so that 空正文不会冒充一条文字评价
17. As a 浏览者, I want 课程×教师总推荐度继续汇总本次推荐度并带上样本数, so that 我不会把维度均分当成总推荐度
18. As a 浏览者, I want 看不到「推荐教师」这类由小样本派生的标签, so that 评价少的老师不会被系统点名推荐
19. As an 管理员, I want 审核队列能识别一条评价用的是哪套规则、哪个版本, so that 我知道当时学生答了哪些题
20. As an 管理员, I want 给课程绑定六类评价规则之一, so that 后续投稿按正确问卷校验
21. As an 管理员, I want 给课程打上或去掉 mooc 标签, so that 网课不再要求线下签到题
22. As a 目录补充申请者, I want 随附评价也走同一套必答规则, so that 申请通过后转入审核的评价不会缺维度
23. As a 维护者, I want 评价规则定义只存在一份并带版本号, so that 前端问卷和后端校验不会再漂移
24. As a 维护者, I want 改规则只追加新版本、不改已发布版本, so that 历史评价仍能按当时规则解释
25. As a 维护者, I want 维度分数存在可演进的分数映射里而不是继续加宽表列, so that 以后加题不必每次改表结构
26. As a 维护者, I want 后端按课程当前规则写入版本、不信任前端传来的规则名, so that 投稿者不能自选更松的问卷
27. As a 维护者, I want 旧评价保持原样且规则字段为空, so that 启用新规则不会回填或伪造默认维度
28. As a 维护者, I want 存量未人工归类的课程先有一个确定的默认规则, so that 投稿在人工归类完成前仍可进行
29. As a 测试维护者, I want 用现有投稿接口测试证明缺维被拒、齐套被收、网课跳过点名, so that 规则变更有一条稳定的回归缝
30. As a 测试维护者, I want 用公开评价流接口测试证明只有新规则评价带维度均分, so that 展示合同不会 silently 退化
31. As a 测试维护者, I want 用浏览器走完投稿页必答与网课跳题, so that 问卷渲染和接口校验看到的是同一套适用题目

## Implementation Decisions

- 权威定义放在共用的评价规则模块。六类 `schemeKey`：`major`（专业类）、`ideology`（思政类）、`math`（高等数学类）、`public_basic`（公共基础类）、`english`（大学英语类）、`pe`（体育类）。首版每类同一份公共核心，不追加特有维度。
- 公共核心维度（均为 1–5 整数）：`teaching`（上课表现）、`attendance`（点名频率，仅线下适用）、`grading`（给分情况，主观措辞）、`workload`（考核压力）。本次推荐度沿用现有 `overall` 列，题干与量表跨类型、跨版本不变。补充说明沿用现有评价正文列，是唯一选填项。
- 适用题目的唯一计算点：输入为课程的评价规则 + 课程标签，输出为本次必答维度列表。投稿接口、投稿页、维度均分都调用它，禁止各写一套过滤。
- 存储采用 expand：任课评价新增规则键、规则版本、维度分数映射；课程新增规则键（可空）和课程标签（多值，首个标签为 `mooc`）。`courses.category` 的 `general | sports` 公开展示 / 目录基线语义本轮不收缩，避免一次改爆目录导入与体育公开展示。
- 未人工归类时的默认规则：目录 `sports` 对应 `pe`，其余对应 `major`。这只是开工默认，不是最终归类；存量人工归类另开人工工单。
- 投稿接口拒绝缺少任一适用维度、拒绝范围外分数、拒绝前端自报的规则版本。成功写入时由后端快照课程当时的规则键与版本，并把适用维度写入分数映射。退役宽表维度列本轮停止写入，删除列放到后续收缩工单。
- 目录补充申请的随附评价走同一校验；申请通过后转入审核队列的评价必须带规则快照和分数映射。
- 公开文字评价流继续只收录有补充说明的条目。对新规则评价额外返回维度均分（本次实际必答维度的算术平均，一位小数）；旧评价与历史评价不返回该字段。流内用官方 Chip 显示均分，不展示分维度。
- 课程×教师总推荐度继续只汇总 `overall`，展示必须带样本数；不新增「推荐教师」标签，不按小样本排名。本轮不新做关系级总推荐度区块。
- 生产前端挂上投稿页。问卷用官方 Form、横向 RadioGroup（1–5）、TextArea（补充说明）、Label / Description / FieldError。题目从适用维度列表渲染，不使用旧的按模板类型拼字段表。
- 带 `mooc` 标签时，请求里若仍带上仅线下维度，接口拒绝（视为无效多余字段），避免前后端各执一词。
- 首版不做后台规则编辑器，不把高分率/及格率做成统计数，不为每类追加特有维度，不把 `mooc` 做成第七类评价规则。

## Testing Decisions

- 只测对外行为：给一组课程规则与标签，投稿接口收或拒什么；公开评价流是否带维度均分；投稿页是否渲染同一批必答题。不测内部函数名或列是否存在。
- 主缝一：现有任课评价投稿接口测试。覆盖：只有推荐度被拒；公共核心四题 + 推荐度被收；缺一题被拒；`mooc` 课程不交点名被收；`mooc` 课程仍交点名被拒；正文可空；规则由后端快照。
- 主缝二：现有公开评价流投影测试。覆盖：带规则快照且有补充说明的条目返回维度均分；历史评价 / 无规则旧评价不返回；无补充说明的新规则评分不进入文字流但仍计入推荐度样本。
- 主缝三：新增投稿页浏览器测试。覆盖：选择非网课后必须看到四道维度题和推荐度才能提交；选择 `mooc` 课程后看不到点名频率；提交载荷与接口必答集合一致。
- 评价规则解析器可以有模块测试，但不得成为第二套策略来源；HTTP 与浏览器测试失败时以适用题目计算点为准。
- 目录补充申请、管理端改规则/标签沿用现有申请与后台接口测试风格，只断言对外收拒与回读字段。
- 先验：`test/reviews.test.ts`、`test/review-projection.test.ts`、`test/catalog-requests.test.ts`、`test/browser/public-review-flow.browser.test.ts`。

## Out of Scope

- 六类各自的特有维度与最终题干打磨（后续以新规则版本发布）
- 后台评价规则编辑器
- 把 `courses.category` 一次性改成六类枚举，以及目录基线导入管道的同步改造
- 存量课程的人工归类本身（另开 `ready-for-human` 工单）
- 删除退役宽表维度列
- 关系级总推荐度新区块、推荐教师标签、小样本隐藏阈值
- 历史评价补维度或参与维度均分
- 目录补充申请页本身的生产挂载（投稿页可暂不展示该入口）

## Further Notes

- 来源栏目映射已写入 ADR-0021：主要课程→专业类，数学课→高等数学类，思政课→思政类，美育→公共基础类，大英/视听说/外教→大学英语类，体育课→体育类；MOOC 栏目按学科归六类并打 `mooc` 标签。本规格的默认规则只解决「未归类也能投稿」，不替代该映射。
- 公开评价流目前只展示有正文的条目；维度均分 Chip 加在这些条目上，不要为了展示均分把无正文评分拉进文字流。
- 生产路由目前没有投稿页；本规格要求挂上，否则浏览器主缝无法成立。
