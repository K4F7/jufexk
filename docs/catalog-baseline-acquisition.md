# 教务目录基线采集规格

> 状态：访谈进行中。本文只记录已确认的范围、约束与验收标准，不代表已经授权实现或执行全量采集。

## 目标

通过获授权账号的一次人工登录会话，从“可见开课全量”建立“可见任课关系全量”目录基线，并为课程、教师与任课关系生成可审计的导入数据。基线之后的少量遗漏或新增走目录补充申请。

当前网站尚未录入真实课程目录；另有一份历史评价资料正在独立清理。因此基线阶段不存在大规模存量教师自动合并问题，两条流水线的身份归属与执行顺序需要显式决定。

教务目录基线先完成并经人工批准，成为课程、教师与任课关系的权威身份来源。历史评价只通过经审核的别名映射引用基线对象；无法匹配的历史对象进入人工别名或目录补充队列，不直接创建正式目录对象。

## 已确认范围

- 遍历当前账号可见的全部已发布学期、可查询维度与分页；不宣称覆盖从未开设、未发布或账号无权查看的对象。
- 仅纳入江西财经大学本校单位开设的开课班，覆盖本校全部培养层次；排除外部或合作院校独立开设的课程。
- 使用版本化、人工确认的本校单位代码清单判定归属，名称仅用于展示；未知代码、同代码异名或内外部信号冲突进入人工复核。
- 麦庐、枫林、蛟桥是本校校区辅助信号，不单独决定课程归属。非 `MOOC` 的线下本校开课应出现三者之一；`MOOC` 可无实体校区。非空但无法识别的地点证据进入人工复核；校区与地点同时为空时确定性记为 coverage exception，不猜测地点，也不删除由单位代码确认归属的目录记录。
- 教务系统原样展示的来源教师名是来源侧稳定身份；系统自带的重名数字后缀必须保留，采集器不得自行增删后缀。
- 来源教师名和课程名同时保存原始值与最小规范值；规范化只做 Unicode NFC、去除首尾空白、将连续不可见空白压成一个普通空格，不改字、不转简繁、不删除数字后缀或姓名内部空格。
- 不同原始值规范后发生碰撞时保留全部原值并进入异常队列，不得静默合并；课程身份仍以课号为准。
- 空教师名不生成教师或任课关系，并单独计数；明确的 `待定`、`未安排`、`外聘`、`教师组` 等占位值进入排除报告，疑似占位但无法确定的值进入异常队列。
- 课号、课程名、评价模板类型和本校归属均有效时，即使教师为空或为占位值，课程本身仍进入目录基线；覆盖声明单独统计无教师课程，后续可通过目录补充申请增加任课关系。
- 一个来源字段包含多名教师时，只按已由 fixture 验证的明确格式拆分；任何陌生分隔或结构进入异常队列，不得把整串文字创建成单个教师。
- 教师表增加唯一来源教师身份字段；教师院系直接迁移为可空、可人工修正的属性，不得使用课程承担单位伪造教师院系。
- 教务基线新建教师时允许院系为空；后台以后补充院系只更新属性，不改变教师身份，也不断开任课关系或评价。
- 教务课程以课号作为来源侧稳定身份；同课号跨学期名称变化不创建新课程，最新已发布学期名称作为当前名称，其他名称作为来源证据保留。
- 同一学期同一课号出现实质不同名称时进入人工冲突队列；缺少课号的来源记录不得自动导入。
- 评价模板类型直接迁移为 `general | sports`，不保留旧枚举兼容期：任何学期存在明确体育性质证据时写入 `sports`，即使来源同时标注必修或选修；没有明确体育证据的课程一律写入 `general`，不得从课程名称猜测体育性质，也不得因性质文字缺失或必修/选修冲突而阻断。
- `general` 使用统一普通课程评价模板，`sports` 使用体育课程评价模板。投稿只选择任课关系，不让学生选择必修或选修。
- KINGOSOFT 原始必修、限选、任选、选修、体育等性质与分类文字必须保留在采集包和批准包的显式溯源字段中，但不扩展为业务分类层级。
- KINGOSOFT 分类数字代码在首批来源快照固证前只作溯源，不参与自动归一化；体育模板选择只依赖明确页面文字。
- 任课关系采用全部可见已发布学期的历史并集：同一课程—教师跨学期重复只生成一条正式关系，不因后续停课删除。
- 批准包为每条任课关系保留首次观察学期、最后观察学期、出现次数和来源证据引用；这些是溯源信息，不改变任课关系本身不含学期的定义。
- 正式交付只包含课程、教师与任课关系，不生成或导入开课班；学期、完整班号与原始表格行仅作为覆盖、去重和审计证据保留。
- 校区、周次、上课时间与地点不进入本次标准化目录；未来若需要开课班，可从保留的原始证据重新派生。
- 用户人工登录后启动采集；采集器不保存账号密码、不逆向登录、不处理验证码、不导出会话令牌。
- 基线是一次性采集，不建设常驻同步服务。
- 每个查询页保留原始 GBK HTML、脱敏请求参数和 SHA-256；来源快照只存放在 Git 忽略的本机受控目录，不进入业务数据库。
- 来源快照不得包含账号密码、Cookie 或会话令牌；标准化数据不保留人数、上课时间或地点。
- 活跃采集目录保留到目录基线成功导入、历史评价完成映射且稳定运行 90 天；随后将完整采集包压缩加密并转入受控离线长期归档。
- 仓库只永久保留批准包 schema、非敏感覆盖摘要与内容哈希，不保留原始 HTML。

## 已确认来源事实

- 课程安排查询向 `/taglib/DataTable.jsp?tableId=5327042&clientWidth=...` 提交表单。
- 翻页向 `/taglib/DataTable.jsp?currPageCount=N` 提交同一查询条件。
- 响应为 `text/html;charset=GBK`，每页约 100 条，并在页面脚本中声明总记录数。
- 可提取字段包括课程代码与名称、学分、总学时、课程类别、承担单位、校区、班号、任课教师、周次、上课时间、地点和授课方式。
- 只保留“本科 + 2025 级”并清空院系、专业及其他筛选后，2026-2027 学年第一学期返回 2120 条；同条件限定软件工程专业时返回 201 条。这证明“培养层次 + 年级”的宽查询可以覆盖多个院系与专业，适合作为主采集维度。

## 两阶段结构

- 浏览器采集阶段运行在用户已人工登录的同源页面，只负责查询计划、串行请求、重试、分页计数、来源快照、检查点和采集包导出，不执行课程或教师业务合并。
- 浏览器采集器以仓库内维护的本地 Tampermonkey 用户脚本交付，只匹配 `https://jwxt.jxufe.edu.cn/*`，不加载外部脚本，不向教务系统之外的主机发起请求。
- 用户脚本提供开始、暂停、继续和导出采集包操作，使用 IndexedDB 保存检查点与来源快照；页面刷新或重新登录不得清空已完成单元。
- 离线派生阶段从采集包生成覆盖声明、课程、教师、任课关系、冲突清单和导入 CSV；解析或归并逻辑改变时只重跑离线阶段。
- 采集包必须版本化，包含来源快照、脱敏查询参数、计划单元状态、计数和 SHA-256，不得包含账号密码、Cookie 或会话令牌。
- 采集包是版本化目录而非浏览器内生成的压缩文件：根目录包含 `manifest.json`、`queries.jsonl` 和按查询编号组织的 `snapshots/<query-id>/page-xxxx.html`。
- 用户从采集面板主动选择本地目录，脚本逐页写入来源快照，避免在内存中组装整个批次；IndexedDB 仅保存运行检查点与恢复所需状态，不作为长期证据库。
- 浏览器脚本与离线解析器均使用 Bun + TypeScript，并共享采集包 schema 与类型；离线命令位于 `scripts/`。
- 解析、分页、课程归并、教师归并、任课关系去重和冲突门禁必须使用脱敏 HTML fixture 编写 Vitest，并纳入现有 `bun run check`。

## 操作边界

1. 用户人工登录教务系统，选择采集目录并点击开始；浏览器随后无人值守运行，直到完成、熔断或登录失效。
2. 采集完成后，用户运行一次 `bun run catalog-baseline derive <capture-dir>`；离线阶段自动解析、执行门禁并生成异常队列或目录基线批准包。异常决定完成后重跑同一命令，不增加整包审核。
3. 批准包就绪并完成暂存预览后，管理员执行一次生产导入。

浏览器不得自动启动本地进程，两阶段之间不建设常驻本地桥接服务。

## 批次门禁

- 批次开始时冻结学期、培养层次、年级和单位代码表及其内容哈希，整个批次只执行由该版本生成的查询计划。
- 批次结束时重新读取来源选项；发生新增、删除或改名时标记 `source_changed`，生成只覆盖变化组合的补充批次计划，不把变化静默并入当前批次，也不重跑未受影响的已完成单元。
- 主查询矩阵为每个已发布学期下全部可选的“培养层次 × 年级”组合；院系、专业、校区、来源课程性质、课程名、教师名和开课单位均留空。
- 各组合结果在本地按来源身份去重，不为获取相同结果遍历院系、专业和开课单位的笛卡尔积。
- 全量结束后随机选择若干专业和开课单位作反证查询；其结果必须全部包含在宽查询并集中。发现遗漏时，相关筛选维度升级为正式矩阵并重新生成覆盖声明。
- 每个计划查询是独立、可恢复的工作单元；失败只重试该单元，不使已完成单元重跑。
- 所有查询严格串行，避免教务系统以会话保存的分页状态被并发请求相互覆盖。
- 正常请求间隔随机为 0.8–1.5 秒，每完成 100 页主动暂停约 20 秒。
- 请求超时、连接中断、HTTP 429 或 5xx 最多重试 3 次，采用约 2 秒、5 秒、15 秒退避并加入随机抖动。
- 收到 HTTP 429 时优先遵守 `Retry-After`；没有该响应头则暂停至少 60 秒。连续两次 429 或 5xx 后自动熔断，等待人工确认会话与站点状态。
- 登录失效不消耗普通重试次数；采集立即暂停并保存检查点，重新人工登录后继续。
- 单页解析失败或查询组合的解析记录数与服务器总数不一致时，只重新执行该查询组合；连续两轮仍不一致才进入例外清单。
- `complete`：所有计划查询均完成，分页连续，每页解析成功，解析记录数与服务器声明总数一致。
- `complete_with_exceptions`：存在重试后仍不可访问的计划查询，覆盖声明逐项记录其范围、错误、尝试次数与最后一次时间；每项必须获得明确人工终态。
- 会话失效时保存检查点；重新人工登录后只继续未完成单元。
- 除 `complete` 或全部例外均有终态的 `complete_with_exceptions` 外，任何批次不得生成目录基线批准包。

## 自动审核

- 复用历史评价流水线的冻结清单、确定性记录清单、金标准、分层队列、逐条异常处理、批准数据包、排除报告和输出哈希。
- 不复用截图 OCR、双模型对抗分析、LLM 仲裁或 GPU 门禁；结构化 HTML 由确定性解析器处理。
- 满足全部不变量的记录自动进入目录高置信集合，不需要逐条或整批人工批准；所有异常进入小规模逐条处理队列。
- 异常项只有三种有效终态：`include`（经人工确认或修正后纳入，并记录原值、修正值、理由与审核人）、`exclude`（确认不属于范围、无效或重复，进入排除报告）、`coverage_exception`（来源无法获取，记录缺失范围与原因）。
- `skip`、`later`、`uncertain` 或空决定均不是终态，继续阻止目录基线批准包生成。
- 金标准至少包含 100 条经人工核对的任课关系，并跨不同学期、培养层次和本校单位分层抽取；若可见任课关系总量不足 100 条，则全量进入金标准并记录实际数量。
- 金标准强制覆盖跨页边界、HTML `rowspan` 续行、同课多教师、教师数字后缀、同课号改名、MOOC、线下三校区、空字段和异常页面；人工只核对课号、课程名、来源教师名及关系身份。
- 目录高置信集合在冻结金标准上的身份映射错误必须为零；每发现一个生产解析缺陷，必须将其证据加入金标准作为永久回归样本。
- 相同采集包离线派生两次必须产生完全相同的输出哈希。
- 当异常项全部获得终态且其他门禁通过时，系统自动编译并批准目录基线批准包，不再要求第二次人工批次确认。
- 异常审核界面为离线生成的 `catalog-review.md`，固定包含 `summary`、`unit_decisions`、`course_conflicts`、`teacher_conflicts`、`coverage_exceptions` 和 `golden_sample` 六节。
- Markdown 只允许表达固定枚举决定与必要修正值；程序必须验证决定合法性、来源键完整性和审核字段后再编译批准包。Markdown 永不得直接导入数据库。
- `bun run catalog-baseline review <quality-directory> [--output <review-directory>]` 同时导出 `catalog-review.md` 与同名的六份确定性 UTF-8 CSV。所有视图绑定质量包哈希并保留来源证据；它们都不是权威导入数据源，只有验证后编译的 JSONL 决定与 approved 包具有权威性。

## 批准与导入

- 离线派生阶段生成版本化 `catalog-baseline.jsonl` 目录基线批准包，包含课程、教师、任课关系与来源身份；采集包本身不得直接导入。
- CSV 和校对表只作为人工复核界面，不是权威导入源。
- 批次状态依次为 `capturing`、`captured`、`derived`、`review_required`（仅有异常时）、`package_ready`、`staged`、`imported`；失败状态记录所处阶段和可恢复检查点。
- 全部门禁通过且异常项均有终态时，由派生器自动进入 `package_ready` 并产生批准包；这不是生产写入。管理员明确执行导入后才可从 `staged` 进入 `imported`。
- 后台对整个批准包执行一次预览；只有零阻断错误时，管理员才可执行一次明确的生产导入操作，原子性写入全部课程、教师与任课关系。
- 批准包按块上传到独立暂存区，每块校验包身份、序号、行数和内容哈希，支持只重传缺失或损坏的块；暂存写入不得改变正式目录。
- 全部块到齐后，服务端重算整包哈希并执行完整预览；最终发布从暂存区在单次数据库事务中写入三类正式对象。
- 最终事务失败时正式目录必须保持为空，暂存数据保留用于检查和重试。
- 基线导入通常要求课程、教师与任课关系均为空。若生产存量已经承载开课班或学生投稿，只有在现有 Course 来源课号、Teacher 来源教师名和 Relation 复合身份全部可证明为批准包的严格子集时，才允许在同一事务中承接其稳定 ID、补齐批准包并以批准包更新当前名称/类别；任一身份不在批准包内即整体阻断，且不得自动删除。承接前必须保存可恢复快照。
- 首次成功导入后记录批准包批次 ID、schema 版本、内容哈希与导入时间，并永久关闭基线专用入口；后续变化只走目录补充申请。
- 基线导入不得通过现有三个 CSV 接口串行提交；任何写入失败必须使整个基线提交不生效。

## 留存和离线归档

- `bun run catalog-baseline archive <capture-directory> --derived <derivation-directory> --approved <approved-directory> [--output <archive-manifest.json>]` 会重新验证三阶段 manifest、全部声明文件的 records/bytes/SHA-256 和跨阶段 hash 绑定，再生成确定性的 `catalog-baseline-archive-manifest/v1` 完整性清单。
- 仅生成清单不代表留存期已经开始。基线正式发布和历史评价映射二者都完成前，清单必须保持 `retention_pending`，`triggerCompletedAt` 与 `archiveEligibleAt` 必须为空。
- 两项工作完成并稳定运行后，以较晚的完成时间作为触发时间，连续保留 90 天；期间任何需要重新映射或重新发布的实质修复都会重新计算稳定期。
- 到期后先复验清单，再将 capture、derived、approved 和清单整体加密转移到受控离线归档。确认离线副本可解密且哈希一致后，才可清理活跃原始快照；仓库和线上环境只保留 schema、非敏感汇总、manifest hash 与归档交接记录。
- 未匹配历史身份只能进入 alias exception 或 Catalog addition request；归档操作不得把这些异常静默变成正式 Course、Teacher 或 Relation。

## 派生物契约

- 采集包：`manifest.json`、`queries.jsonl`、`snapshots/<query-id>/page-xxxx.html`。
- 确定性派生：`inventory.jsonl`、`courses.jsonl`、`teachers.jsonl`、`relations.jsonl`、`conflicts.jsonl`、`exclusions.jsonl`、`coverage.json`。
- 人工界面：`catalog-review.md`（附六份确定性 UTF-8 CSV 分表视图）。
- 权威交付：`approved/manifest.json` 与 `approved/catalog-baseline.jsonl`。
- 所有 JSON/JSONL 契约必须携带 schema 版本；清单记录每个文件的字节数、记录数和 SHA-256。

基础离线派生命令为 `bun run catalog-baseline derive <capture-directory> [--output <derivation-directory>]`。未指定输出目录时写入采集目录的同级 `<capture-directory>-derived`；命令先完整验证采集包，再以严格 GBK 解码离线生成 `inventory.jsonl`、`courses.jsonl`、`teachers.jsonl`、`relations.jsonl`、`exceptions.jsonl` 和 `manifest.json`，不发起网络请求。对应 schema 为 `catalog-baseline-inventory/v3`、`catalog-baseline-course/v1`、`catalog-baseline-teacher/v1`、`catalog-baseline-relation/v2`、`catalog-baseline-exception/v1` 与 `catalog-baseline-derivation/v1`。inventory v3 保留来源性质与分类文字、承担单位稳定代码与标签、校区和地点原文；承担单位标签只允许通过采集包内已哈希冻结的字典唯一映射到代码，未知或歧义映射进入异常。relation v2 的 provenance 同时保留培养层次与年级，供覆盖和金标准分层使用。异常派生物仍是可审计中间结果，不是批准包，也不得直接导入数据库。

## 实现顺序

1. **领域与数据库迁移**：增加课程课号唯一身份、教师来源身份与可空院系；将评价模板类型、历史评价包及所有 API/UI 校验直接迁移到 `general | sports`，并把既有 `required`、`elective` 数据确定性迁移为 `general`。
2. **采集包契约与浏览器采集器**：定义共享 TypeScript schema，完成限定域名和权限的 Tampermonkey 脚本、查询计划冻结、串行分页、重试、熔断、检查点与目录写入。
3. **离线确定性派生**：实现 GBK HTML fixture 解析、`rowspan` 继承、课程/教师/任课关系归并、来源身份、覆盖声明、冲突与排除报告、确定性哈希。
4. **审核与批准包**：生成并验证 `catalog-review.md`，建立至少 100 条金标准，落实三种异常终态，自动编译 `package_ready` 批准包。
5. **暂存与原子导入**：实现分块断点上传、整包哈希与预览、空目录门禁、单次事务发布、失败回滚、成功后永久关闭入口。
6. **试采与全量运行**：先用少量学期/层次/年级完成端到端 pilot 和反证查询，固定页面字典证据与金标准；通过后执行一次全量基线，再让历史评价流水线映射到正式目录身份。

每个工作包都必须在 `bun run check` 中有对应验证；原子导入测试必须证明任一步骤失败时正式目录保持为空，采集安全测试必须证明采集包中不存在 Cookie、会话令牌或账号凭证。
