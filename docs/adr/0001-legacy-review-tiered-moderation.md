# 历史评价采用 GPU OCR-first 分级审核流水线

状态：已接受；单元格审核编排见 [ADR-0019](./0019-grok-workflow-legacy-review-package.md)（冻结后可用 Grok workflow；截图与矩阵冻结仍不得使用 Grok）

日期：2026-07-28

权威规格：GitHub issue #24

## 背景

历史评价必须逐格忠实提取、保留来源证据并最终由人工批准。早期方案把整个图片或工作表矩阵交给长生命周期模型会话：截图结构偏差或单次模型失败会使整组失败，也会重复消耗图片输入和输出 token。它无法稳定断点续跑，也不适合全量资料。

本批历史资料在人工规范化后建立网站的初始课程目录；当前网站实体不是匹配权威。任务不得写腾讯表格或业务数据库。

## 决策

采用两阶段、严格分层的 GPU OCR-first 证据流水线。先完成固定 8 组冒烟并通过绑定式批准门禁，再进入全量。每个阶段严格按以下顺序运行：

1. 完成该阶段全部截图；
2. 执行 Capture QA；
3. 冻结记录 SHA-256 的 manifest；
4. 使用本机 NVIDIA GPU 执行 RapidOCR；
5. 从来源截图派生可追溯的单元格裁图；
6. 对路由单元格执行隔离的 A/B 审核与必要仲裁；
7. 执行机器验收；
8. 生成人工复核 Excel；
9. 从明确人工决定编译版本化批准数据包。

任何重截都创建新的 manifest 版本并保留旧证据。来源截图不可被裁图替代。

## 冒烟与全量门禁

统一 v6 冒烟必须在同一 2K 窗口条件下重新捕获，不混用 v3、v4 或 v5 图片。固定范围为：主要课程 19--26；数学课、美育、大英和视听说、思政课、MOOC 8--14；外教 3--6；体育课 6--14。

冒烟批准必须绑定输入 manifest 哈希、识别契约版本、提示词版本和模型配置；任一绑定值变化都会使批准失效。只有有效批准文件才能解锁独立的全量命令。全量截图覆盖各工作表实际使用范围，保留真实行号、中间空行和合并课程上下文；必须先截完全部图片，再统一 OCR，最后统一 Agent 审核。

冒烟通过要求：8 组均有明确 Capture QA 终态；每个工作表至少一条非空评价完成 OCR、A/B 与仲裁路径；完整矩阵键覆盖率 100%、键唯一且上下文引用有效；CUDA 已被真实证明；失败重试能隔离到批次或单元格；重复显示表头仍可区分；未发生外部写入。

## Capture QA 与证据身份

Capture QA 核对实际工作表、首尾原始行、上下文与评价行对齐、表头、列覆盖、裁切、可读性和课程锚点。结论为 `accepted`、`recapture_required` 或 `manifest_mismatch`。只有结构问题可以阻断课程组。

稳定单元格键为 `工作表名 + 原始行号 + 来源列字母`。显示表头作为独立元数据保留，因此体育课的重复表头不构成冲突。逐行上下文索引和完整单元格矩阵由确定性程序生成；模型只审核被路由的单元格，不创建或删除矩阵键。

原始截图、裁图、OCR token、模型输出与最终记录之间必须保留来源哈希、坐标、预处理参数和派生哈希。所有内容型证据与交付物必须位于经过验证的 Git ignored 根目录。

## GPU OCR

复用 RapidOCR 3.9.1 与 ONNX Runtime GPU。检测、方向分类和文字识别三个会话都必须使用 `CUDAExecutionProvider`；CUDA 不可用时立即停止 OCR，不得静默回退 CPU。

原图 OCR 结果按来源图片 SHA-256 缓存。置信度不足或疑似漏字时执行单独保留的增强 OCR pass，并保存置信度、坐标和预处理参数。置信度不直接产生 `agreed`：`>= 0.95` 且无几何或上下文警告视为高置信候选，`0.85--0.95` 优先审核，低于 `0.85`、缺少置信度或疑似漏字必须执行增强 pass。

## 单元格审核与恢复

模型任务只包含同一工作表内最多 8 个相邻单元格；长文本可进一步缩小。分析 A 接收裁图和 manifest 派生的同行上下文，但不接收 OCR 文本。分析 B 额外接收 OCR token、置信度和坐标。A、B 不得看到彼此输出，也不得读取 issue、ADR、仓库说明、Git 状态或其他项目上下文。

每个任务与尝试必须记录输入哈希、模型、契约版本、会话 ID、原始响应、退出状态、Schema 错误和重试历史。恢复运行跳过输入和配置未变化的成功阶段，只重跑受影响任务及下游。

失败按以下顺序缩小：

1. 在干净 Luna 会话重试失败批次；
2. 二分批次并分别重试；
3. 缩小到单格 Luna 重试；
4. 单格仍失败时依次使用 5.5、5.4 各重试一次。

既有 Codex/Luna runner 仍按上列 5.5/5.4 回退。冻结后若改走 [ADR-0019](./0019-grok-workflow-legacy-review-package.md) 的 Grok workflow，则用干净子 agent 重试、二分、单格，不再把 Grok 当作 Luna 转写后备，也不走 Codex 5.5/5.4。尝试耗尽时仅把该格标记为 `unresolved: agent_exhausted`，保留原始错误和恢复条件；其他成功格保持有效，整组不得因此失败。

## 一致性、仲裁与组状态

`raw_transcription` 永不覆盖。只有 A/B 原文精确一致、无纠错、标点差异、疑字或上下文冲突时才能成为 `agreed`。仲裁比较图片、OCR、A 与 B，只能选择、标记差异或保留未解决状态，不得发明第三版流畅文本。

组终态仅为：

- `completed`：结构通过且所有必需单元格均完成；
- `completed_with_exceptions`：结构通过，但存在内容不确定或耗尽的单元格；
- `capture_blocked`：Capture QA 发现结构问题。

不得使用笼统的终态 `failed` 隐藏原因。

## 人工复核与交付边界

机器权威交付采用版本化 JSONL；Excel 只是人工复核界面。工作簿覆盖已一致项、异常、实体决定、OCR 证据、A/B 差异、任课关系、失败和重试历史，人工只在明确的决定、批准正文和备注列输入。

程序把 Excel 中明确的人类决定编译为新的批准数据包，而不是直接导入工作簿。批准数据包包含课程、教师、任课关系、历史评价、未解决项、证据、manifest 和导入报告。冻结审核包中，独立图文核验通过的记录可由 [ADR-0020](./0020-verifier-gated-auto-approval.md) 标为已批准；映射仍须完整。实际网站导入属于后续独立授权流程。

## 安全与边界

- 不写腾讯表格或业务数据库；
- 不自动合并有歧义的课程或教师别名；
- 不发布未经人工批准的 OCR 或模型文本；
- 不把原始截图、OCR token、评价正文、模型日志、Excel 或数据包纳入 Git；
- 仓库只保留工作流代码、测试、Schema、ADR 和不含敏感内容的聚合文档。

## 被否决或取代的方案

- **整图或整组长会话生成完整矩阵**：单次失败影响范围过大，输出容易缺键且不可经济恢复。
- **OCR 置信度直接批准**：置信度不是内容真实性或上下文正确性的证明。
- **仲裁即批准、人工只抽查**：违反公开内容必须人工确认的约束。
- **直接导入 Excel**：人工界面不是机器权威格式，无法可靠约束版本与映射完整性。
- **以当前网站目录匹配历史资料**：当前目录不完整，本批资料才是初始目录来源。

## 后果与验收

该决策增加了 manifest、任务状态、证据链和版本化交付的实现成本，但把重试范围缩小到单元格并使全流程可恢复、可审计。

确定性测试必须覆盖 manifest 哈希与不可变性、稳定列字母键、重复表头、完整矩阵、OCR 路由、重试/二分/模型回退、严格一致性、组状态聚合、批准失效和批准包过滤。GPU 集成测试必须真实断言三个 OCR 会话都启用 CUDA。代表冒烟记录必须使用真实隔离模型调用，假执行器只能验证确定性故障状态。
