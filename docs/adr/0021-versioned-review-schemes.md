# 版本化任课评价规则：代码权威定义、JSON 分数与稳定推荐度

状态：已接受

日期：2026-08-18

权威规格：GitHub issue #66

修订：[ADR-0012](./0012-general-sports-review-template-kinds.md) 中 `courses.category` 作为评价模板二值（`general | sports`）的语义。课程分类改为六类评价规则；「修读属性不入课程分类、来源文字仅作溯源、课程特点用独立多值标签表达」的结论继续有效。第一版问卷题目、补充说明必填与维度均分范围见 [ADR-0023](./0023-ustc-aligned-four-tier-questions.md)。

## 背景

任课评价问卷目前只有 `overall` 必填，其余维度选填；维度定义散落在前端问卷、legacy 模板、API 校验和宽表列中，且已出现漂移（退役维度残留、前后端字段不一致）。#66 要求一份权威、版本化的评价规则驱动前端问卷与后端校验，适用评分题全部必答，补充说明为唯一选填的一段文字。

## 决策

1. **权威定义在代码**：单一模块（`src/lib/review-schemes.ts`）导出六类规则（专业类、思政类、体育类、高等数学类、公共基础类、大学英语类）的版本化定义：`schemeKey` + 版本号 + 不可变维度清单（维度 id、题干、1–5 量表说明）。前端问卷渲染与后端必答校验共用同一定义。改规则等于追加新版本，已发布版本永不修改。首版不做后台规则编辑器。
2. **存储**：`reviews` 新增 `scheme_key`、`scheme_version` 列，维度分数写入 `scores` JSON 列（维度 id → 1–5 整数）。scheme 由后端按课程当前绑定的规则写入，不信任前端传值。退役的宽表维度列停止写入，择机清理。
3. **推荐度是显式一题**：保留 `overall` 列作为「本次推荐度」，题干与量表在所有规则类型、所有版本中保持完全一致。「课程 × 教师总推荐度」只汇总它，因此规则版本升级不破坏可比性。维度均分只是单条评价内必答维度的算术平均，展示为一个 Chip，不跨条聚合；未来若聚合维度分数，必须按 `scheme_key + scheme_version` 分组。
4. **主观报告，不伪装统计**：给分情况、挂科风险等维度一律用主观量表措辞（「你感受到的给分」），展示处标注为同学主观反馈，禁止用百分比或「高分率/及格率」等统计口径呈现。
5. **公共核心 + 少量特有维度**：四题公共核心——上课表现、点名频率、给分情况、考核压力——六类共用；各类最多追加两个特有维度（逐类打磨后以新版本发布，首版允许六类只用公共核心上线）。适用评分题必须全部作答，补充说明是唯一选填项且合并为一段文字。
6. **MOOC 是课程标签，不是规则类型**：沿用 [ADR-0012](./0012-general-sports-review-template-kinds.md) 的独立、多值课程标签机制，`mooc` 标签表示网课形式、没有线下签到。规则定义中的维度可标记为「仅线下适用」（如点名频率）；带 `mooc` 标签的课程问卷不展示这些维度、也不必答，后端按 scheme + 课程标签计算必答集合，维度均分只算本次实际必答的维度。标签不改变课程的 `schemeKey`。
7. **课程归类**：`courses.category` 从 `general | sports` 迁移为六类 `schemeKey` 枚举，存量课程做一次人工归类；课程固定绑定一套规则，不随投稿者专业变化。来源栏目映射：主要课程→专业类；数学课→高等数学类；思政课→思政类；美育→公共基础类；大英和视听说、外教→大学英语类；体育课→体育类；MOOC 栏目按课程学科归入六类（无明确学科时默认公共基础类）并打 `mooc` 标签。
8. **旧数据不回填**：`scheme_key IS NULL` 即规则启用前的评价，保持原样，不补填、不伪造默认值；维度均分 Chip 只对携带 scheme 的评价渲染。
9. **小样本约束**：总推荐度展示必须携带样本数，不生成「推荐教师」等派生标签，不凭小样本排名。

## 被否决的方案

- **继续宽表加列**：各类规则维度不同且会迭代，每次调整都要做列迁移，且已产生退役列残留，否决。
- **MOOC 单独成规则类型**：MOOC 是授课形式，不是学科；单独成类与 ADR-0012「课程特点用独立标签表达、不扩展模板类型」冲突，还会丢失课程本身的学科归类。改用 `mooc` 标签剔除仅线下适用的维度，否决。
- **由维度均分派生推荐度**：强行给各维度等权，丢失投稿者的综合判断，且与现有 `overall NOT NULL` 数据不连续，否决。
- **规则定义入库 + 后台编辑器**：首版无编辑需求，代码内定义即天然版本化、可 review，否决。
- **高分率/及格率做成统计**：站内没有可验证的成绩分布数据，统计口径是伪装官方概率，否决。
