# 独立图文核验通过后，审核包记录可以自动批准

状态：已接受

日期：2026-08-18

权威规格：GitHub issue #208

修订：[ADR-0019](./0019-grok-workflow-legacy-review-package.md) 第 7 条「approved 恒为 false」，以及 [ADR-0001](./0001-legacy-review-tiered-moderation.md)「仅人工批准进入最终导入集」中针对本冻结审核包的部分。网站生产导入仍是后续独立授权，本决策不写腾讯表格或业务库。

## 背景

#179 的 workflow 能无人值守产出机器审核包，但一律不批准。用户要求在 A/B 与仲裁之后再加一个独立 agent：对照原图和得出的正文，通过后自动批准。

仲裁本身仍不能批准。自动批准只来自这次图文核验，并且必须失败闭合。

## 决策

1. **核验输入**：独立 agent 只读取裁图 / 公式栏图、公式栏正文、冻结上下文中的课名与教师。看不到 A/B 互相的完整对话，不得发明第三版通顺稿，不得改公式栏正文。
2. **失败闭合**：`approved=true` 仅当同时成立：`body_matches_source=true`、`mapping_supported=true`、`evidence` 非空、格子已是 `agreed`/`arbitrated`、正文来源是公式栏、有裁图、有冻结课名。核验失败、缺失或证据为空则保持未批准。
3. **系统性画面冲突**：公式栏与格子画面冲突时，只要公式栏正文仍是存储真值且映射成立，仍可批准正文；不得因常见截断把整表打回人工。
4. **续跑**：已批准格不再进入 A/B 或核验。同一 `out_dir` 接着跑只核验未批准格。
5. **交付边界**：自动批准只写 gitignored 审核包。不写腾讯表格、不写业务数据库、不把证据纳入 Git。生产导入仍需单独授权。

## 被否决的方案

- **仲裁即批准**：仲裁只选边，不是图文核验，否决。
- **核验失败当通过**：违反失败闭合，否决。
- **自动写入生产库**：超出本工单，否决。
