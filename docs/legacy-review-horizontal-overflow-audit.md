# 历史评价横向溢出审核

## 目标

重新审核全部 1972 条历史评价，确认每条记录对应一个真实的非空来源单元格，而不是相邻评价横向显示时覆盖的空单元格。先通过公式栏非空检测建立评价起始单元格清单，再以强疑似记录冒烟验证清单与审核方法，最后扩展至全量。

## 证据与判定不变量

- 每个候选单元格必须同时保留单元格地址、单元格画面文字和上方公式栏原值。
- 公式栏原值是来源真值；单元格画面文字只用于定位、可见文本比对和识别横向溢出范围。
- 定位阶段先逐格读取公式栏；只有公式栏非空的单元格才能进入评价起始单元格清单。
- 公式栏非空时，该单元格是一个评价起始单元格，评价正文取公式栏完整原文。
- 公式栏为空但格内显示文字时，该单元格是横向溢出覆盖的空格，不生成独立评价。
- 格内文字可以因列宽而截断，不要求与公式栏逐字等长，但可见部分必须能与公式栏对应。
- 公式栏与格内文字无法对应时，结论为证据冲突，不得自动通过。

## 证据保留

- 全部 14,985 格保存工作表、单元格地址、公式栏原值、是否非空、文本哈希和读取顺序。
- 所有公式栏非空格额外保存单元格画面，并将可见文字与公式栏原文比对。
- 110 个强疑似格无论公式栏是否为空，都保存单元格画面。
- 地址错位、读取失败或文本无法对应时保存完整截图，并进入证据冲突队列。
- 普通公式栏空格不逐格截图。
- 分批写入检查点；中断后只从最后一个已确认地址继续。

## 定位协议

- 每一行的首个评价列通过地址框直接跳转，并核对活动单元格地址。
- 同一行后续列使用右方向键依次移动；每次移动后重新核对活动地址。
- 切换工作表、换行或恢复检查点时重新通过地址框定位，不依赖滚动位置。
- 公式栏原值连续读取两次且完全一致后才记录。
- 活动地址不一致或两次公式栏读取不同，立即停止当前批次并保存冲突截图。

## 冒烟门槛

- 全量定位前先审核全部 110 个强疑似单元格。
- 110 格的活动地址必须全部与目标地址一致，且每格两次公式栏读取完全一致。
- 每格必须同时具有公式栏结果和单元格画面证据，并归为评价起始格、横向溢出空格或证据冲突。
- 已人工核对案例必须与自动结果一致。
- 出现无法解释的错位或冲突时，先修正定位方法，不进入 14,985 格全量扫描。

## 数据重建规则

- 现有记录对应公式栏非空格时保留，正文采用公式栏逐字原文。
- 现有记录对应公式栏空格时，作为横向溢出误记录排除。
- 公式栏非空但现有 1972 条中没有对应记录时，作为漏项补入后续审核队列。
- 每个评价起始单元格只生成一条历史评价，不按显示文字横跨的列数复制。
- 证据冲突项不进入批准数据包。
- 只生成新的离线 overlay、数据包及验证报告，不修改腾讯表格。

## 遍历与检查点

- 按冻结矩阵的八张工作表顺序执行；表内按原始行号递增，每行从最左评价列向右读取。
- 每 25 个来源行提交一个原子检查点，记录首尾地址、读取数量、非空数量、冲突数量和内容哈希。
- 每张工作表完成后核对计划格数与已读取格数相等，再进入下一张表。
- 重跑按截图关联键去重；已经确认且哈希一致的记录不重复覆盖。

## 已知范围

- 全量：1972 条历史评价，分布在 612 个“工作表 + 来源行”组中。
- 定位矩阵：完整遍历 14,985 个评价单元格，以公式栏非空检测评价起始单元格；不得只遍历现有 1972 条记录。
- 矩阵覆盖：主要课程 3696 格、体育课 1648 格、外教 1576 格、大英和视听说 1568 格、思政课 1584 格、数学课 1631 格、美育 1746 格、MOOC 1536 格。
- 强疑似：52 个组、110 条记录；同一行相邻来源列的评价正文完全重复。
- 宽松候选：439 个组、1799 条记录；同一来源行存在至少两个评价来源列。

## 最终验收

- 冒烟阶段 110/110 格通过地址绑定、公式栏双读和画面对照后，才允许执行全量定位。
- 全矩阵 14,985/14,985 格各有且仅有一个终态，不缺键、不重键，且八张工作表计数分别闭合。
- 每个公式栏非空格保存完整原文并完成单元格画面对照；每个现有评价归入保留、横向溢出排除或证据冲突之一。
- 新发现的评价起始单元格全部进入漏项审核队列；相邻正文重复只有在两个公式栏都非空时才保留为两条评价。
- overlay、数据包、暂存和验证产物确定、哈希可复核，身份映射保持不变，未解决冲突不得进入批准输出。
- 自动测试通过，腾讯表格、生产 API 和业务数据库保持只读。
